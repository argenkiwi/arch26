Calling koinInject<P>() in a connected Pane and then using the presenter inside retainMolecule re-resolves the @Factory presenter (and its dependency graph) on every recomposition; retain keeps only the first instance and silently discards the rest. Use retainPresenter<P>() (retainMolecule.kt), which reads currentKoinScope() in composition and calls scope.get<P>() inside the non-composable retain lambda, as recommended in InsertKoinIO/koin discussion #2334. Presenters stay @Factory because retain owns their lifetime. Separately, retainMolecule used to launch into the activity-wide retained CoroutineScope, so popped screens kept their molecule running; it now launches into a child SupervisorJob scope held by a RetainObserver that cancels it in onRetired and onUnused (the latter covers values created but never retained).
